# Markdown 지원 범위

## 문서 목적

이 문서는 Visual Markdown Editor가 다룰 Markdown 문법의 제품 정책을 정의한다. 아래 상태는 현재 구현 완료 여부가 아니라 목표 범위다. 실제 지원 여부는 Milkdown 연결 후 fixture 기반 round-trip 테스트와 수동 편집 테스트를 통과한 항목만 지원된 것으로 판단한다.

## 상태 정의

- **MVP 지원**: MVP에서 시각적 편집과 Markdown 직렬화를 제공하고 데이터 보존을 검증해야 한다.
- **이후 지원**: MVP에서는 전용 편집 기능을 제공하지 않으며, 안정화 이후 별도 작업으로 검토한다.
- **검증 필요**: 파서와 직렬화 과정에서 원문을 안전하게 보존할 수 있는지 아직 확인되지 않았다.
- **지원하지 않음**: 제품 범위에서 의도적으로 처리하지 않으며 Visual Editor에서 편집하지 않는다.

## 문법별 정책

| 문법 | 상태 | MVP 정책 및 검증 기준 |
| --- | --- | --- |
| Paragraph | MVP 지원 | 일반 문단을 입력·수정하고 한글, 영문, Unicode가 의미 손실 없이 직렬화되어야 한다. |
| Heading 1~6 | MVP 지원 | 제목 레벨 1~6을 생성·변경하고 한글과 inline formatting을 포함한 내용 및 레벨이 보존되어야 한다. |
| Bold | MVP 지원 | 굵게 서식을 적용·해제하고 선택 영역의 의미가 보존되어야 한다. |
| Italic | MVP 지원 | 기울임 서식을 적용·해제하고 선택 영역의 의미가 보존되어야 한다. |
| Strikethrough | MVP 지원 | 취소선을 적용·해제하고 Markdown으로 다시 직렬화할 수 있어야 한다. |
| Inline code | MVP 지원 | 인라인 코드를 적용·해제하고 내부 특수문자와 백틱 경계를 검증해야 한다. |
| Link | MVP 지원 | 링크 생성·수정·제거를 지원하고 표시 텍스트와 URL을 보존해야 한다. |
| Bullet list | MVP 지원 | 글머리 목록과 중첩 구조를 편집하고 항목 경계를 보존해야 한다. |
| Ordered list | MVP 지원 | 번호 목록과 중첩 구조를 편집하고 순서 의미를 보존해야 한다. |
| Task list | MVP 지원 | 체크리스트 항목과 체크 상태를 편집·보존해야 한다. |
| Blockquote | MVP 지원 | 인용문을 생성·수정하고 내부 문단 구조를 보존해야 한다. |
| Code block | MVP 지원 | 여러 줄 코드, 들여쓰기, 언어 식별자가 있는 fenced code block을 검증해야 한다. |
| Image | MVP 지원 | 로컬 workspace 파일을 상대 경로 image로 첨부하고 Webview에서는 렌더링 전용 URI로 표시한다. 저장되는 `src`는 상대 Markdown 경로여야 하며 공백, 한글, 괄호, `#`, `%` 및 상위 폴더 경로를 검증한다. |
| Table | MVP 지원 | GFM 표 삽입, 행·열 편집, 삭제 및 현재 열의 Left/Center/Right 정렬을 지원한다. 여러 열 CellSelection에서는 selection head 열만 정렬하며, Source/Visual 왕복과 저장 후 GFM alignment marker 보존을 검증해야 한다. |
| HTML | 검증 필요 | Raw HTML이 파싱·직렬화 과정에서 변경되거나 제거되는지 확인하기 전까지 Visual Editor 편집을 경고한다. |
| HTML comment | 검증 필요 | 주석의 내용과 위치가 그대로 보존되는지 확인하기 전까지 Visual Editor 편집을 경고한다. |
| Front matter | 검증 필요 | 구분자, 키 순서, 값 형식이 보존되는지 확인하기 전까지 Visual Editor 편집을 경고한다. |

## 데이터 보존 원칙

1. Extension과 Webview는 렌더링된 HTML이 아니라 Markdown 문자열을 교환한다.
2. “MVP 지원” 항목도 자동·수동 검증 전에는 사용자 문서에서 안전하다고 주장하지 않는다.
3. 문법의 공백이나 마커가 달라져도 의미가 같은 경우와 원문 문자열이 완전히 같은 경우를 구분해 기록한다.
4. 파서가 알 수 없는 노드나 문법을 발견하면 저장 과정에서 조용히 제거하지 않는다.
5. 보존이 확인되지 않은 문법이 포함된 문서는 Visual Editor에서 경고하고 기본 Markdown Text Editor 사용을 안내한다.
6. 하나의 문서에 지원 문법과 미검증 문법이 섞인 경우에도 미검증 부분을 덮어쓸 수 있는 저장을 허용하지 않는다.

## 지원 판정 기준

문법별 상태를 실제 지원으로 판정하려면 다음 조건을 모두 충족해야 한다.

- 해당 문법을 포함한 fixture가 존재한다.
- Markdown 파싱 후 직렬화 결과를 원문과 비교했다.
- 문자열 차이가 있다면 의미 보존 여부와 허용 근거를 문서화했다.
- Visual Editor에서 생성, 수정, 제거하는 동작을 확인했다.
- 한글 또는 Unicode와 함께 사용할 때 입력과 직렬화가 안정적이다.
- 외부 변경, 저장, Undo, Redo 흐름에서 데이터가 손실되지 않는다.

검증 결과가 이 정책과 다르면 지원 범위를 넓혀 주장하지 않고, 상태를 `검증 필요` 또는 `이후 지원`으로 낮춘 뒤 제한 사항을 기록한다.
